Откройте приложение через ярлык запуска

Этот файл — интерфейс к локальной службе аудита. Открытый напрямую с диска, он не работает: браузер по соображениям безопасности запрещает страницам с файловой системы обращаться к серверу приложения.

Запустите ЗАПУСТИТЬ.cmd в каталоге приложения — браузер откроется сам по адресу http://127.0.0.1:7345, и всё заработает.

Лицензионный ключ

Программа распространяется по ключу. Введите ключ, выданный владельцем продукта, — он действует сутки, затем понадобится ввести его снова. Ограничений на число вводов нет.

Чтобы закрыть программу, просто закройте это окно.

Что нужно сделать с базой?

Три раздела. Обследование и проверка качества кода только читают и собирают отчёт; обновление переводит конфигурацию на новый релиз и, если вы это подтвердите, записывает результат в базу.

Обследование информационной базы

Укажите путь к базе — система сама выгрузит конфигурацию, разберёт код, расширения, права и данные и соберёт отчёт об обследовании. Изменения в базу не вносятся: все операции выполняются в режиме чтения.

Файловая база — путь к каталогу. Серверная — «сервер\имя_базы» или «сервер:порт\имя_базы».

    Обновление конфигурации

    Если конфигурация типовая и стоит на поддержке — обновление выполняется средствами платформы, без сравнения и объединения: своих правок нет, значит и решать нечего, весь новый релиз применяется целиком. Программа проверяет это сама, за пять секунд, до начала работы.

    Если в конфигурации есть доработки — выполняется трёхстороннее объединение: программа сравнивает основную конфигурацию и новую поставку с текущей конфигурацией поставщика, сама переносит изменения поставщика, сохраняет ваши доработки и показывает дважды изменённые места — те, где решение может принять только человек.

    Файловая база — путь к каталогу. Серверная — «сервер\имя_базы» или «сервер:порт\имя_базы».
    Нужны права «Администрирование»: конфигурация выгружается и загружается.
    Не сохраняется на диск, используется только в этом запуске.
    Список установленных на этом компьютере платформ.
    Обычно указывать не нужно: текущая поставка лежит в самой выгрузке — выгружая конфигурацию на поддержке, платформа кладёт .cf поставщика рядом с её настройкой (Ext\ParentConfigurations), и программа берёт его оттуда. Не нашлось — поставка восстанавливается из базы по сравнению с поставщиком. Файл понадобится, только если не вышло ни то, ни другое: тогда сохраните его сами (Конфигуратор → Конфигурация → Поддержка → Настройка поддержки → «Сохранить в файл») либо возьмите дистрибутив ровно того релиза, который стоит сейчас, — его программа сначала поищет сама в каталогах шаблонов обновлений 1С. Здесь поставщик нужен для объединения, поэтому без него прогон остановится и попросит файл, а не продолжит «как получится».
    То, на что обновляемся: файл поставки .cf либо каталог её XML-выгрузки.
    Сюда выгружаются три конфигурации, и здесь же остаётся результат объединения — пока он не загружен в базу, спорные места правят прямо в этих файлах, из них же потом загружается конфигурация. Нужно несколько гигабайт свободного места.
    По умолчанию — тема программы из «Параметров»; здесь её можно поменять для этого отчёта. На печать выбор не влияет: в PDF отчёт всегда выходит светлым, чтобы не заливать лист краской.

      Проверка качества кода

      Только замечания к коду: по критичности, по разработчикам, с поиском и фрагментами кода. Движок проверок тот же, что в обследовании, — здесь нет ни оценок состояния, ни объёма данных, ни трудозатрат.

      Файловая база — путь к каталогу; серверная — сервер:порт\имя.
      Обычно заполнять не нужно — если база на поддержке, программа возьмёт конфигурацию поставщика прямо из неё. Указанный здесь файл или каталог используется вместо этого. Проверяются только доработки: типовой код поставщика не проверяется никогда. Если поставщика нет ни в базе, ни в этом поле, проверяется вся конфигурация целиком — в отчёте об этом сказано прямо.
      Путь к хранилищу или к каталогу, где их несколько, — по одному в строке. Кнопка «Каталог…» дописывает выбранный путь новой строкой. Хранилища опознаются по файлу cfgrepo.conf, и программа найдёт их сама — и основной конфигурации, и расширений.
      Пользователь и пароль хранилища здесь не нужны: файлы читаются напрямую, а не через платформу.
      По одному адресу в строке (tcp://сервер/хранилище, годится и http://). Порт по умолчанию — 1542; если он другой, пишется в адресе. Адреса перечисляются вручную: списка хранилищ сервер не отдаёт, перебрать их нечем.
      Вместе со служебной базой указывайте только те адреса, к которым эта база уже подключена — основной конфигурацией либо одним из расширений. Программа распознает по адресу, чьё это хранилище; к чужому адресу она не пойдёт и базу переподключать не станет.
      Пользователь хранилища, а не базы: у хранилища свой список пользователей. Со служебной базой это должен быть тот же пользователь, под которым она подключена к хранилищу.
      Для работы с хранилищем программа заводит временные файловые базы. Файловой базе нужна лицензия 1С на этой машине; если её нет («Не найдена лицензия»), укажите здесь готовую базу — лучше серверную, ей лицензию выдаёт сервер 1С. Через неё программа подключится к хранилищу. Серверная база пишется как Srvr="сервер";Ref="база";, файловая — путём к каталогу.
      В эту базу программа не пишет ничего и ни при каких условиях — только читает. Годится рабочая база разработчика: она же и даёт код для проверки, поэтому должна быть обновлена из хранилища.
      Хранилища расширений читаются через те расширения, которые в этой базе уже есть, — своё программа не заводит. Поэтому база должна быть подключена к указанным хранилищам, и открыть её конфигуратором на этой машине нужно хотя бы раз: привязка хранится в профиле конфигуратора.
      Фрагменты кода, внесённого каждым помещением. Программа получает их сравнением соседних версий хранилища, а версию платформа отдаёт только целым файлом конфигурации. Когда развернуть его нечем (работа через служебную базу), это десятки минут на одно помещение на больших конфигурациях — при «Автоматически» фрагменты в таком случае не строятся, и отчёт об этом говорит. Дерево помещений, авторы и замечания к коду остаются в любом случае.
      Проверяются только объекты, помещённые за этот период: это и есть работа разработчиков. Пусто — вся история хранилища.
      Список установленных на этом компьютере платформ.
      Сюда пишутся выгрузки на время проверки.
      Обычный Markdown: разделы, пояснения и блоки ```правило с параметрами. Списки внутри правил не ограничены — дописанная строка в таблице запрещённых методов или в перечне областей начинает работать сразу. Кнопка «Сохранить шаблон…» кладёт на диск образец со всеми проверками, которые программа умеет выполнять; его и правят под требования проекта.
      Правило, которого программа не знает, прогон не рвёт: такой пункт пропускается, а отчёт называет его отдельной строкой — обещать проверку, которой нет, продукт не станет.
